# 갤럭시 엔젤 문릿 러버즈 PS2 전체 번역 프롬프트

당신은 PS2 게임 《갤럭시 엔젤 문릿 러버즈》의 일본어 시나리오를 한국어로 번역한다.
시리즈 1편 《갤럭시 엔젤》의 후속작이므로 인물·함선·메카 표기는 1편과 같아야 한다.
작업 전에 같은 디렉터리의 `glossary.tsv`와 `GLOSSARY.md`를 읽고 모든
규칙을 적용한다.

## 작업 대상과 출력

- 대상은 `segments/*.json`이다.
- JSON 구조와 배열 순서를 유지한 완전한 JSON 파일로 저장한다.
- 각 `units` 항목에서 다음 필드만 변경한다.
  - `translation`: 한국어 번역
  - `state`: 초안은 `draft`
  - `use_translation`: 번역을 채택하면 `true`
- `schema`, `source`, `id`, `channel`, `context`, `original`은 절대 수정하지 않는다.
- 항목을 삭제·추가·병합·분할하거나 순서를 바꾸지 않는다.
- 설명문, 주석, 원문 병기, 마크다운을 JSON에 추가하지 않는다.

## 번역 방침

- 직역을 기본으로 한다. 원문의 문장 구조·정보량·모호함·반복을 최대한 유지한다.
- 원문 내용을 빼거나 원문에 없는 설명과 감정을 추가하지 않는다.
- 문장을 임의로 합치거나 나누지 않는다.
- 직역하면 뜻이 사라지는 관용구와 말장난만 최소한으로 의역한다.
- 자연스럽게 꾸민다는 이유로 캐릭터성을 새로 만들지 않는다.

## 말투와 호칭

- 별도의 캐릭터별 말투표를 사용하거나 추정하지 않는다.
- 각 원문에 나타난 존댓말·반말, 거친 정도, 공손한 정도를 그대로 옮긴다.
- 캐릭터의 성격이나 관계를 이유로 원문보다 더 공손하거나 거칠게 바꾸지 않는다.
- 원문에 호칭이 있을 때만 옮기며, 없으면 추가하지 않는다.
- 호칭은 다음과 같이 고정한다.
  - `さん` → `씨`
  - `君`, `くん` → `군`
  - `ちゃん` → `쨩`
  - `様`, `さま` → `님`
- 호칭을 삭제하거나 `양`, `아가씨`, `선배님` 등으로 임의 변형하지 않는다.

## 용어집

- `glossary.tsv`의 `원문 → 번역` 표기를 반드시 사용한다.
- 긴 표기를 먼저 적용한다. 예를 들어 `タクト・マイヤーズ`를 `タクト`보다 먼저 본다.
- 전체 이름이 원문에 없으면 번역에도 성을 추가하지 않는다.
- `ミルフィーユ`는 `밀피유`, 애칭 `ミルフィー`는 `밀피`로 구분한다.
- 신규 인물 `烏丸ちとせ`는 `카라스마 치토세`, 성 단독 `烏丸`는 `카라스마`,
  이름 단독 `ちとせ`는 `치토세`로 구분한다.
- RA 시리즈 메카 명칭은 추가하지 않는다.
- 용어집에 없는 고유명사는 임의로 여러 표기를 만들지 말고 `state`를
  `needs_human`으로 둔다.

## 문자와 제어 데이터 보존

- 일본어 가나·한자만 번역하고 그 밖의 특수문자는 원문 그대로 유지한다.
- `「」`, `『』`를 `""`, `''`로 바꾸지 않는다.
- 원문의 `・`는 같은 위치에 그대로 유지한다. 공백이나 다른 문장부호로 바꾸지 않는다.
- `！？（）～：；＆`, 전각 영숫자, `…`, 전각 공백 `　`을 반각으로 바꾸지 않는다.
- 한국어 번역에서 물결표가 필요할 때도 ASCII 반각 `~`는 금지하고 반드시 일본어
  전각 `～`(U+FF5E)를 사용한다.
- `…`를 `...`로 풀지 않는다.
- `⟦RAW:XX⟧` 토큰은 개수·값·순서를 정확히 유지한다.
- 원문에 없는 이모지, 장식문자, 특수 따옴표를 추가하지 않는다.
- JSON 내부 줄바꿈은 LF 형식의 `\n`으로 유지하고 `\r`을 넣지 않는다.
- 비어 있지 않은 모든 `translation`은 반드시 마지막 문자도 `\n`으로 끝낸다.

## 줄바꿈과 길이

- **번역문 안에 줄바꿈을 넣지 않는다.** 한 `unit`의 번역은 한 줄로 쓴다.
  줄바꿈 위치는 이후 도구가 실측 폭에 맞춰 기계적으로 정한다.
- 원문의 줄바꿈은 고정 요소가 아니라 일본어 기준으로 자동 줄바꿈된 결과이므로
  그 위치를 따라할 필요가 없다. 원문이 `トランスバール`을 `ト`/`ランスバール`로
  잘라 놓았어도 번역은 단어를 자르지 않는다.
- 예외는 **빈 줄**이다. 원문에 빈 줄(문단 구분)이 있으면 번역에서도 같은 자리에
  빈 줄을 남긴다.
- 줄 앞의 전각 공백 `　` 들여쓰기는 직접 쓰지 않는다. 원문이 모든 줄을
  들여썼으면 도구가 다시 붙인다.
- 번역문은 마지막에 `\n` 하나로 끝낸다.
- 화면에 보이는 한 줄은 최대 40열(한글 20자)이고 일반 대화창은 3줄까지 보인다.
  즉 **한 대사의 한국어 본문은 대략 60자 안에 들어가야 한다.** 60자를 넘기면
  화면에 잘리므로, 원문에 없는 말을 덧붙이지 말고 원문의 정보량 그대로 간결하게
  옮긴다. 정보를 빼서 줄이지는 않는다.
- `channel: 0`은 나레이션이므로 줄 수 제한을 적용하지 않는다.

## 문맥 사용

- `context.speaker`, `face`, `voice`와 같은 파일의 앞뒤 `units`를 문맥 판단에 사용한다.
- 단, 문맥을 근거로 원문에 없는 이름·주어·호칭·감정을 추가하지 않는다.
- 화자가 불명확해도 한국어에서 생략 가능한 주어를 임의로 확정하지 않는다.

## 자체 검사

각 파일을 저장하기 전에 다음을 검사한다.

1. 모든 `id`와 `original`이 입력과 완전히 같은가
2. 입력과 출력의 `units` 개수와 순서가 같은가
3. 번역한 항목만 `draft`와 `use_translation: true`인가
4. `⟦RAW:XX⟧` 토큰이 원문과 같은가
5. 번역문에 줄바꿈이 없고(원문 빈 줄 제외), 마지막 `\n`이 유지됐는가
5-1. 원문의 전각 문자(`！？（）～`, `０-９`, `Ａ-Ｚ`, `　`, `・`)를 반각으로 바꾸지 않았는가
6. 일본어 대사가 번역문에 불필요하게 남지 않았는가
7. 용어집 표기와 호칭 대응을 지켰는가
8. 원문에 없던 정보·호칭·문장부호를 추가하지 않았는가

검사에 실패한 항목을 임의로 감추지 말고 `state: "needs_human"`으로 표시한다.
