원문은 표(적 함선 종류·수량을 2열로 배치)와 3개 구획(편성/승리/패배)이 빈 줄로

**원인**: `moonlit_lovers_reflow_translations.py`의 `reflow()`가 번역문을 `\n` 기준으로
나눈 뒤 **공백 하나로 모두 합쳐서 재래핑**한다. 이 로직은 "한 대사 = 한 논리 줄"인
일반 대화에는 맞지만, 이 표 형식 화면처럼 **원문 자체가 여러 구획으로 나뉜 화면**에는
맞지 않는다. `unit_indent()`가 인식하는 두 들여쓰기 패턴(전체 들여쓰기/첫 줄만 들여쓰기)
중 어느 쪽에도 해당하지 않아 원문 구조가 보존되지 않은 채 통째로 이어 붙는다.

**규모**: `channel: 0`이면서 전각 공백 2회 이상 + 줄바꿈 4회 이상인 "표 형식" 유닛
37건 중 34건이 헤더 뒤 줄바꿈 누락으로 확인됐다(정규식 `(조건|편성)～[^\n]` 매칭 기준).
전투 시작 전 브리핑 화면이므로 **전투가 있는 미션마다 반복 노출**된다.

**대응 방향**: 이 화면 전용 처리(구획 경계마다 강제 줄바꿈 유지, 2열 표는 재래핑 대상에서
제외)를 리플로우 도구에 추가하거나, 이 37건을 별도 authoring 규칙으로 수작업 재배치해야
한다. 일반 대화 리플로우 로직을 그대로 적용하면 안 된다.

```bash
python -c "
import glob, json, re
for f in sorted(glob.glob('assets/translation/segments/*.json')):
    data = json.load(open(f, encoding='utf-8'))
    for u in data['units']:
        if u.get('channel') == 0 and '敵部隊の編成' in (u.get('original') or ''):
            tr = u.get('translation') or ''
            if re.search(r'(조건|편성)～[^\n]', tr):
                print(f, u['id'])
"
```

## F2. 전각 문장부호(！？、。)가 일반 대화 9,298건에 남아 있다 — 대화의 36.5%, 139개 파일 전체

> 일반 한국어 대사에는 일본식 `、。！？`를 남기지 말고 `, . ! ?`를 사용한다. 화면 정렬이나

그런데 `channel: 1`(일반 대화) 25,471건 중 **9,298건(36.5%)이 여전히 전각 `！`/`？`를
쓰고 있다.** 표본:

| id | 원문 | 현재 번역 |
|---|---|---|
| `SCENARIO_DAT_00003000:dialogue:0040` | `ミルフィー！\nタクトだけど……入ってもいいかい？` | `밀피！ 택트인데…… 들어가도 될까？` |
| `SCENARIO_DAT_00003000:dialogue:0045` | `えっ……！？` | `엣……！？` |
| `SCENARIO_DAT_00003000:dialogue:0061` | `タクト！？\nいいわよ、入って入って！` | `택트！？ 괜찮아, 들어와, 들어와！` |

139개 세그먼트 파일 **전부**에서 발견되어 특정 배치 작업의 국지적 실수가 아니라
번역 전체에 걸친 미적용 규칙으로 보인다. 규칙이 정해지기 전(또는 확정 후 소급 적용 전)
번역분이 그대로 남아 있는 것으로 판단된다. 기계적으로 `！`→`!`, `？`→`?`, `、`→`,`,
`。`→`.` 일괄 치환이 가능하지만, **표/브리핑처럼 전각이 의도된 예외가 섞여 있을 수
있으므로 일괄 치환 전 표본을 사람이 확인**해야 한다(철칙 9).

## F3. 장음부호 `ー`가 물결표 `～`로 바뀐 곳 — 205건, 전부 한 방향

`AGENTS.md`·번역 프롬프트 모두 "원문의 장음부호 `ー`는 번역에서도 `ー`, 물결표 `～`는
번역에서도 `～`로 유지하며 **서로 바꾸지 않는다**"고 명시한다. 그런데 원문에 `ー`만 있고
`～`가 없는 유닛 중 205건이 번역에서 `ー` 없이 `～`만 쓰고 있다. **반대 방향(원문 `～`가
번역에서 `ー`로)은 0건** — 즉 "말끝을 늘이는 `ー`를 한국어 관용 표현 `～`로 옮기는" 일관된
패턴이다.

| id | 원문 | 현재 번역 |
|---|---|---|
| `SCENARIO_DAT_00003000:dialogue:0075` | `う、うわーい。\nうれしいなー。` | `우, 우와아. 기쁘다～.` |
| `SCENARIO_DAT_00006800:dialogue:0151` | `まずはポテトフライから。\nはい、あーんしてください。` | `우선 감자튀김부터. 자, 아～ 하세요.` |
| `SCENARIO_DAT_00006800:dialogue:0162` | `……あー、うまかった。\nごちそうさま。` | `……아～, 맛있었다. 잘 먹었어.` |

**판단 보류 사유**: 갤럭시 엔젤 C6 사례(반각 `~`가 실기에서 위치·크기가 작게 그려져
전각으로 확정)처럼, 이 프로젝트도 특정 글리프의 실기 렌더링을 직접 보고 표기를 확정해
왔다. `ー`를 그대로 쓴 표시가 실기에서 어색하게 보여 `～`로 바꾼 것인지, 아니면 규칙을
놓친 것인지는 **실기 확인 없이는 판단할 수 없다.** 205건 전부 같은 방향이라는 점은
"의도된 스타일 선택"과 "규칙 인지 없이 매번 같은 습관으로 옮김" 둘 다와 부합해 이 결과만으로
결론 내릴 수 없다. 사람이 실기(또는 에뮬레이터)에서 `ー`가 정상적으로 보이는지 확인한 뒤
규칙 준수 여부를 확정해야 한다.
